# Domain docs

This is a single-context project. Before exploring or designing, read the root GLOSSARY.md and any relevant decisions in docs/adr/. If a GLOSSARY-MAP.md is introduced later, follow it to relevant context glossaries instead.

Use the glossary's canonical vocabulary in code, tickets, tests, and explanations. Surface contradictions with relevant ADRs before proceeding.

When a term is resolved, use domain-modeling to record it. Create ADRs only for significant, hard-to-reverse trade-offs. Missing domain files are not a setup failure; create them lazily when there is something to capture.
